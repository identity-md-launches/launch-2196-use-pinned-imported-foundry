# Cabal launch adaptation

This adapts the imported project for Robinhood Chain 4663, `univ4_hook` / LaunchFactory. It preserves LaunchToken, CabalFundingHook and the separately operated Node/SQLite worker. No public deployment, paid oracle validation, game hosting or live worker activation occurred. The implementation review below is not an independent audit or IMD admission.

## Imported audit dispositions

The IDs below identify the supplied imported audit; its nine entries include informational coverage/trust observations.

1. **`c0d049b09d5df785246c95506336a11956638cda898e58401414b396123e9409` — reproduced, fixed.** Before changes, 2,500 characters entered the queue with zero preflight calls. The live free check returned HTTP 400 and `question: Too big: expected string to have <=2000 characters`. Tests now cover 2,000/2,001, 2,500, surrogate pairs and malformed Unicode. No paid request was made to reproduce this.
2. **`f1b8b57bebed32e534a0389fa7406f6c4f772181a0e7a440f9d4a586e470dde0` — reproduced, fixed at the payment gate.** The imported decision-style fixture received `ambiguous_question` and `not_answerable` blockers. The queue and engine now refuse it before payment. Contrary to the suggested full-body POST, the live `/requests/check` schema rejects `v`, `window`, `quorum`, `validForSeconds` and `guards`; supported wording projection plus strict local body validation is the working integration. The public arithmetic smoke sample passed. Private game wording is still a separate integration prerequisite; no invented decision semantics or automatic `allowAmbiguous` bypass is supplied.
3. **`d505e5f4eea39e1c0e564b962866016eb76b67031e3074a786ad490a1d2ef24e` — reproduced, fixed.** A local pre-change test spent 1 IMD under a raised cap for one request although the current price is 0.5. The exact-price check rejects that before any effects. Changed-price/rollback tests pass and the fork payment through actual Intake runtime still debits exactly 0.5 IMD.
4. **`75fe2166599eb74c623d0c230fece656334228c02af1a5d93ffb7d58c076df34` — reproduced lifecycle risk, intentionally retained.** A retired action cannot spend the restricted request fund, while swaps and treasury settlement remain functional. Immutable Intake/action and no arbitrary recovery are explicit requirements. Adding migration or a sweep would violate them. Size prefunding to reserved obligations plus the operating reserve; request funds may become permanently stranded if this action is retired.
5. **`e736f82dc360bbd3de6a2762791905579a34f6fee140ce7c6c6acf08f3769563` — reproduced, mitigated.** The original 300-second deadline expires at 301 seconds. The worker now signs with a named 1,800-second deadline. Unit tests retain expiry, and E2E verifies actual signed bytes after 301 simulated seconds, then restart recovery. Arbitrarily long inclusion delay is not solved or promised; no replacement/retry behavior was added.
6. **`6ed8076e4356d6bbdf5262c7cc766684d84665dfcc667c38c9852352e921d047` — confirmed trust assumption, unchanged.** First initialization is manager-only and factory-sender-only. The first compatible IMD/12500 pool binds permanently; the constructor does not take CABAL or pin tick spacing. The authorized factory is trusted to choose the actual launch token/60 spacing. Fork assertions compare `boundPool` to `keccak256(abi.encode(positionOf(number).key))` and check actual currencies/fee/spacing. The final live verification must do the same.
7. **`d2ba0c2d644489158376dd3fc6a107e681d8be0a6bc306bdcdfda0767652cea7` — confirmed, unchanged.** Only `configureWorker` changes authority/spending settings. Owner cannot change economics/destinations or withdraw arbitrarily. Caps are UTC calendar-day caps, allowing spending on either side of midnight. The worker can be disabled but cannot be cleared to zero after configuration. A compromised owner and worker can waste the authorized budget buying requests, never redirect it to an arbitrary payee.
8. **`17e0c8b4c6e2bd1731a2ba898ebaac588c4a768349497155671384f4bbfdccb3` — confirmed default discrepancy, explicit override supplied.** Current policy 30 remains 12500 fee, 2,500 IMD opening valuation and 1000 bps swarm. Its default is 80/10/10. Current public docs support `economics: {poolBps, remainderTo}` for hook launches. `deployment/launch-terms.json` requires 8800/1000/200 and the authorized remainder. Both fork launches accept that allocation. IMD must freeze these terms, rather than copy the default split. There is no invented cap field or paired-IMD deposit.
9. **`e65bf3d681e90ccf3dc0b7c7edc78b1dcb332c1585bc33683d78922d0e6e000e` — coverage updated, not a defect.** Baseline reproduced: 19 Solidity tests with 1,536 fuzz cases and 25 worker tests. Current checks, code hashes and limits are in `reports/validation.json`, `reports/contract-review.txt`, and the fork/protocol reports. No claim of independent audit, browser-wallet testing or live oracle delivery is made.

No reported behavioral finding was dismissed as unreproducible. The migration and factory-binding items are retained requirements/trust assumptions rather than permissions to redesign the project.

## Preserved money flow and limits

Official-pool custom fees remain floor(gross/25) for exact-input trades, ceil(net/24) for exact-output trades, with the imported full-fill checks. They are always IMD claims; swaps never call Intake, an oracle, worker or treasury. `harvest` cumulatively assigns floor(totalHarvested*7/10) to requests and the remainder to the fixed treasury. Donations/prefunding belong entirely to requests. The 12500 platform fee and its 80/20 requester/network allocation remain outside this split. Quotes include custom tax; no second deduction and no flat 5.25% all-in promise is correct.

Reserve eight decisions per BO5: 4 IMD currently, 64 IMD for sixteen simultaneous reservations, **plus** an owner-configured operating reserve and separate native ETH gas. Existing lease/fencing, SQLite full-sync journal, signed bytes before broadcast, duplicate keys and reconciliation remain. Confirmation of payment does not prove admission or a verdict. The supplied package does not implement or activate the separate game coordinator's result-verification/application integration. Production stays disabled pending verified deployment, reserve/gas funding, operational review and a paid live validation.
