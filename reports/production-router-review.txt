CABAL — LOCAL PRODUCTION ROUTER REVIEW

The current compiled token and hook pass both currency orderings through the
actual forked Robinhood LaunchFactory, PoolManager, IMD, Intake, UniversalRouter,
V4Quoter and Permit2 runtimes. See production-router-review.json for snapshot,
runtime hashes, constructor args, salts, local addresses, bound pool IDs and all
assertion results. Protocol addresses/hashes were independently re-read by the
public-read script and compared to the imported pins (protocol-review.json).

Encoding preserves Explorer's extended exact-input struct, minHopPriceX36=0,
UniversalRouter command 0x10 and actions 0x060c0f. Eight quotes equal execution:
buy/sell exact input and exact output in both orderings. Exact output is extra
contract coverage; the UI exposes exact input. The already-tax-inclusive quote
is used directly. Slippage, maximum input, expired deadline, ERC20 and Permit2
approvals, stale price and router residual tests pass atomically.

Oversized sells are refused by V4Quoter with NotEnoughLiquidity(bytes32); smaller
fillable amounts quote. A separate disposable raw-router partial sell asserts
unused CABAL stays with the trader and tax applies only to filled output. This
fixture does not bypass the UI's quote failure or permit unlimited fills in live
integration. Impossible exact output also fails both quoting and execution.

Owner/treasury/remainder/requester use the authorized project wallet. The 88/10/2
allocation is checked before the remainder holder transfers local trade inventory
to the disposable actor. Normal factory liquidity rounding returns 445/443 atomic
CABAL dust to the remainder in these scenarios. LP fee collection remains the
factory's zero-liquidity-change path and its 80/20 requester/network allocation;
custom request reserves are unaffected.

No real transaction, coin launch or oracle admission occurred. The fork uses
local funding and locally impersonated roles only. Fixture launch numbers,
Merkle roots and record metadata are not an IMD attestation. Browser wallet UX,
final deployed pool and paid live request/result validation remain external.
